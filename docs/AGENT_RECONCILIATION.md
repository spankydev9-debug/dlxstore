## 1. The attribution problem (read this first)

**Every commit in this repository is authored by one placeholder identity:**
`spankydev9-debug <YOUR_SPANKYDEV_EMAIL>` (verified with `git log --format='%an <%ae>'`).

Consequences:

- Agent work **cannot** be attributed, bisected by author, or audited per contributor from Git history.
- The only remaining attribution signal is **artifact provenance**: which files/commits a given agent
  documented itself as owning (`BACKEND_CHECKPOINT.md`, migration header comments, session transcripts).
- Everything below is therefore **evidence-based attribution**, not authoritative authorship. Where an
  artifact cannot be attributed, it is listed as *unattributed*.

Fix going forward: configure a real Git identity, and have each agent state its session/agent id in its
own handoff document.

## 7. Preventing a repeat

1. **One owner per area, declared in writing** before work starts; overlapping edits are the root cause of
   C1–C4.
2. **One migration per concern, and check for an existing definition first** —
   `grep -i 'create table.*<name>' supabase/migrations/*.sql` before writing a new table.
3. **No parallel schemas and no parallel clients** for the same feature; extend, never fork.
4. **Verify against the live system**, never against another agent's summary — every claim in a handoff
   needs a command and its output.
5. **Update the checkpoint when reality changes**; never silently rewrite another agent's document.
6. **Real Git identity** so attribution and bisection become possible.

this audit, the image pipeline is genuinely healthy, SEO fundamentals are in place, and the backend agent's
prepared foundation is coherent. The problems are concentrated in **unshipped, unreconciled parallel work**
(the chat stack), in **ordering** (notification writer removed before its replacement), in **one live
security exposure** (coupon enumeration), and in **documentation drift**.
